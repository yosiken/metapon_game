# 1. リズム

本作は「いつでも手を出せる」連続時間のゲームである。
**拍で操作を縛った瞬間にアクティブ連鎖が死ぬ**ため、リズムは**ゲートではなく報酬**として入れる。

## R1. 融解の拍量子化 —— 「氷は拍の頭で融ける」 ✅ **採用済み**

> **本案は採用され、`game-design.md` §4.6 に正式仕様として移された。**
> 以下は提案時の記述。確定仕様（BPM 150、グリッド数での寿命指定、フレーム整合）は仕様書を参照。

**一言**: 音楽を上から被せるのではなく、**盤面が音楽を生む**。

### ルール

`MELT_TIME` の満了時刻を、**次に来る拍（または8分・16分）に切り上げて量子化**する。

```
meltAt = quantizeUp(freezeTime + MELT_TIME, beatGrid)
beatGrid = 60 / BPM / SUBDIV        // SUBDIV: 1(4分) / 2(8分) / 4(16分)
```

結果として、盤面上の複数の氷グループが**拍の頭に揃って融ける**。
融解音（ピシ…）が自然にリズムを刻み、**ゲームが自分でBGMのパーカッションを演奏する**。

### 数値

| Lv | `MELT_TIME` | `SUBDIV` | 実効の融解タイミング（BPM120 = 1拍 0.5s） |
| --- | --- | --- | --- |
| 1〜3 | 0.80 → 0.70 | 1（4分） | 1.0秒（2拍）に揃う |
| 4〜6 | 0.65 → 0.55 | 2（8分） | 0.75秒（1.5拍）に揃う |
| 7+ | 0.52 → 0.40 | 4（16分） | 0.50秒（1拍）に揃う |

- 量子化は常に**切り上げ**なので、氷はわずかに長持ちする。基準 `MELT_TIME` を 0.05秒ほど下げて相殺する。
- レベルが上がるほど `SUBDIV` を細かくする。**難しくなるほど刻みが細かくなる**＝音楽的にも盛り上がる。

### なぜこのゲームらしいか

- §6.4.1 で「氷の亀裂が残り時間を伝える」と決めてある。量子化すると、その視覚情報が**拍という離散的な単位で数えられる**ようになる。アナログな目測がリズムの勘定に変わり、**内面化しやすくなる**。
- 複数の氷グループが同時に融けるため、「どれを捨てるか」の判断が**拍単位で訪れる**。判断の周期が揃うことで、忙しさが混沌ではなくグルーヴになる。
- 3本のスタックの融解タイミングが揃うと、**3つ同時に失う瞬間**が生まれる。緊張の山が音楽的に設計できる。

### リスク

- 量子化でタイミングが揃いすぎ、**判断が「拍ごとの一斉処理」に単調化**する恐れ。対策として、グループごとに `±1 サブディビジョン` の位相オフセットを持たせる案（完全に揃えず、裏拍にも散らす）。
- BPMをレベルで上げるか固定かは要検討。上げると `SUBDIV` の細分化と二重に効いて急峻になる。**BPM固定・SUBDIV可変**を推す。

**実装コスト**: 小（`meltAt` の計算に量子化関数を1つ挟むだけ）

## R2. 潮汐 —— 周期的な浮力の呼吸 ★★★

**一言**: 海が呼吸している。**引き潮のときに凍らせろ。**

### ルール

沈降係数 `G` を楽曲の周期で振動させる。

```
G(t) = G_stage * (1 + TIDE_AMP * sin(2π * t / TIDE_PERIOD))
TIDE_AMP    = 0.15
TIDE_PERIOD = 2小節（BPM120 4/4 なら 4.0秒）
```

`G` が小さい位相＝**引き潮**＝浮きやすい。大きい位相＝**満ち潮**＝沈みやすい。

### 表現

**UIを一切足さない。** 潮汐そのものがメトロノームになる。

- 水の色調と明度が周期で呼吸する。引き潮で水面の光条が強まり、盤面全体が明るくなる。
- マリンスノーの落下速度が周期で変わる。
- BGMの小節頭＝引き潮のピーク。

### なぜこのゲームらしいか

本作の中心的な問いは常に**「今のまま水面まで届くか」**（§6.4 の浮上予測ライン）。
潮汐は、この問いに**「いつ凍らせるか」という時間軸を足す**。
場所（どの列）と深さ（何連鎖）に加えて、**時刻**が3つ目の変数になる。

### リスク

- **待ちゲーになる**恐れ。`TIDE_AMP = 0.15` は意図的に小さい。潮汐が浮上の可否を**決めてはいけない**。良い時に凍らせると楽になる、程度に留める。
- **浮上予測ライン（§6.4）が嘘をつく。** 予測は時間変化する `G` を積分して計算する必要がある。
  実装上は今後2秒ぶんを数値積分すれば足りる（60Hz × 120ステップ、毎フレームでも軽い）。**これは必須の対応**。

**実装コスト**: 小〜中（予測ラインの積分対応が主）

## R3. ビート共鳴 —— 拍に乗せた結氷 ★★

**一言**: 拍の上で凍らせると、音が**調に乗る**。

### ルール

- 結氷が拍から **±80ms** 以内なら**共鳴**成立。
- `chainMult` に **+0.3** 加算。
- 音: 共鳴時は**スケール内の協和音**、非共鳴時は**半音下げた濁った音**で鳴る。

§11.1 で「連鎖数に応じて音階が上がる」と決めてあるので、
**音程＝連鎖の深さ / 音色＝拍の精度** という二軸の楽器になる。

### リスク

- **リズムが取れない人を罰してはいけない。** 非共鳴でもゲームは完全に成立する（スコアが伸びないだけ）。
- 設定に**「リズム補正オフ」**を用意する。オフにすると共鳴ボーナスと潮汐振幅（R2）が消え、`G` は一定になる。
  §11.2 のアクセシビリティ項目として扱う。

**実装コスト**: 小（オーディオのスケジューリング精度が要件。§12.1 で Web Audio 直叩きを選んでいるので問題なし）

## R4. 楽曲駆動モード「潮騒（しおさい）」 ★★

**一言**: レベルカーブを**タイマーではなく曲の構成**が駆動する。

- Aメロ = 低 `dropRate`、長い `MELT_TIME`。仕込みの時間。
- サビ = `dropRate` 急増、`MELT_TIME` 短縮、`SUBDIV` 細分化。処理の時間。
- 落ちサビ = 供給が一瞬止まる。**盤面を片付ける猶予**。
- 曲終わり = クリア。1プレイ2〜3分の固定長。

### なぜ実現可能か

§12.2 で**決定性シミュレーション（シード付きPRNG・固定60Hzステップ）**を採っている。
これは**譜面がそのまま作れる**ということ。供給タイミングを曲に合わせて手で置ける。
リプレイもスコアの再現検証も、既存の仕組みでそのまま動く。

**実装コスト**: 中（譜面フォーマットと作曲が必要。ただし新しいゲームルールはゼロ）

# 2. タイミング

## T1. 際結氷（きわけっぴょう）—— 融ける寸前に繋ぐ ✅ **採用済み**

> **本案は採用され、`game-design.md` §5.8 に正式仕様として移された。**
> 際窓は提案時の「残り15%」ではなく、拍量子化と同じ物差しに乗せた **「最後の1グリッド」** に変更されている。

**一言**: 早く繋ぐな。**ギリギリまで待て。**

### ルール

同一スタック内の氷グループの残り時間が **`MELT_TIME` の15%以下**のときに新たな結氷が発生したら**際結氷**。

- スコア **×1.3**
- 浮力 **×1.15**
- 専用SE（鋭い「ピシッ」）と、亀裂が**逆再生で塞がる**視覚

### なぜこのゲームらしいか

**現状、連鎖は「早く繋ぐほど安全」で、遅らせる理由がどこにもない。**
際結氷は、そこに**初めてリスク/リターンの選択を置く**。
待てば得点と浮力が伸びるが、スタックは減速し続けており、待ちすぎれば失う。

そして待つための情報は**すでに盤面にある**——§6.4.1 の亀裂表示が、そのままタイミングバーとして機能する。
**新しいUIを一切足さずに、新しい判断を作れる。**

### リスク

- 上級者が常に際結氷を狙い、**プレイが遅延方向に最適化**される恐れ。
  対策: 15%という窓は `MELT_TIME` 0.5秒なら **75ms**。安定して狙うには相当な精度が要る。
  加えて、待っている間に瓦礫が降り積もる（§5.7）ので、遅延には自然なコストがある。
- R1（拍量子化）と組み合わせると、**際結氷の窓が拍に紐づいて読みやすくなる**。この2つは相性が良い。

**実装コスト**: 極小（判定1行 + 演出）。**費用対効果は本書で最大。**

## T2. 過冷却チャージ —— 押さえて溜める ★★

**一言**: 凍る直前の水を**押さえつけて**、一気に凍らせる。

### ルール

結氷猶予（`FREEZE_DELAY`, §5.2）中のグループに**指を置いて動かさない**と、過冷却が溜まる。

```
charge = clamp((holdTime - 0.15) / 0.45, 0, 1)    // 0.15秒後から 0.60秒で最大
浮力 ×= 1 + 0.8 * charge
スコア ×= 1 + 1.0 * charge
```

- **溜めている間、そのグループは浮力を一切生まない。** スタックは沈み続ける。
- 指を離す / 最大まで溜まる / 他のブロックが触れる → 即座に結氷（**衝撃で過冷却水が一気に凍る**という実際の物理現象）。

### なぜこのゲームらしいか

- シューティングのチャージショットの構造をそのまま持ち込めるが、**新しい入力は「動かさない」だけ**。ボタンもジェスチャも増えない。
- 過冷却は実在の現象で、**衝撃で瞬時に凍る**という性質が「他のブロックが触れると即結氷」というルールを説明する。設定と機構が一致する。

### リスク

- **指1本を長時間拘束する。** 指は2本しかない（§6.2）ので、溜めている間は実質1本で戦うことになる。
  これは欠点ではなく**コスト設計**として成立しうるが、6列で本当に成立するかはP1で実測が要る。
- 縦ドラッグとの入力競合。「掴んだまま動かさない」の判定しきい値（`DRAG_THRESHOLD = 0.35 cell` 未満の移動を維持）を慎重に決める必要がある。

**実装コスト**: 中（入力判定の設計が本体）

## T3. 同期浮上 —— 3本同時に水面を割る ★★★

**一言**: **3本全部を生かしきった者への報酬。**

### ルール

2本以上のスタックが **0.5秒以内**に水面を越えたら**同期浮上**。

```
関与した全スタックのスコア ×= 1 + 0.5 * (n - 1)     // 2本:×1.5  3本:×2.0
```

演出は**水面が複数箇所で同時に割れる**。音は単音ではなく**和音**。

### なぜこのゲームらしいか

§8.3.1 で本作の核を「指2本 vs 氷塊3本」と定義した。
**しかし現状、3本を生かしきることへの明示的な報酬が存在しない。**
同期浮上は、その核をそのままスコアに変換する。

「どれを捨てるか」というゲームに、「**全部救えないか**」という上の階層を足す。

### リスク

- 狙って作るのが難しすぎる可能性。0.5秒の窓は要調整。
- 偶然の同期に大きなボーナスが出ると価値が薄れる。`n=2` を ×1.5 に抑え、**3本同時にのみ劇的な演出**を割り当てる。

**実装コスト**: 極小（水面通過イベントのタイムスタンプを見るだけ）

# 3. シューティング

**本作におけるシューティング性とは何か**を先に定義する。

> **水面へ昇る氷塊は、すでに「弾」である。**
> 撃つ方向は決まっている（上）。プレイヤーが決められるのは **どの列から / どれだけの勢いで** 撃つか。

つまり **列＝照準、連鎖の深さ＝火力、運動量＝ダメージ**。
この対応さえ作れば、**新しい操作を一切足さずに**シューティングの構造が手に入る。

## S1. 深海生物ボス —— 列で狙い、運動量で撃ち抜く ★★

**一言**: 水面を塞ぐ何かに、**氷塊をぶつける。**

### ルール

- ボスは水面直下に居座り、**2〜3列ぶんの水面を塞ぐ**。
- 塞がれた列のスタックは**通常では水面を越えられない**——ぶつかって跳ね返り、沈む。
- ただし**運動量が閾値を超えていれば突き破る**。

```
momentum = |v_impact| * mass_stack
突破閾値  IMPACT_THRESHOLD = 40
ダメージ  = momentum
```

`v` の上限は 14 cell/s、標準的なスタック質量は 5〜8。
弱い浮上（v=4, mass=5 → 20）では弾かれ、**連鎖を重ねた浮上（v=10, mass=6 → 60）で初めて通る**。

### ボスの行動

| 行動 | 内容 | 対策 |
| --- | --- | --- |
| **触手** | 1列を5秒間**結氷不能**にする | その列を避けて組む |
| **墨** | 画面を暗く濁らせ、**氷の亀裂が読みにくくなる**（§6.4.1 の情報を奪う） | 拍（R1）で数える |
| **投棄** | 瓦礫を一気に落とす | 事前に盤面を低く保つ |
| **移動** | HPが減ると塞ぐ列を変える | 照準を組み直す |

### なぜこのゲームらしいか

- **新しい動詞がゼロ。** 縦ドラッグだけでボス戦が成立する。
- 「どの列で連鎖を組むか」という、これまで自由度でしかなかった選択に**正解と不正解が生まれる**。
- 「墨」は視界ではなく**情報（亀裂＝残り時間）を攻撃する**。本作固有の弱点を突く攻撃であり、他のパズルゲームには移植できない。

### リスク

- ボス戦は**盤面管理より照準が優先される**ため、本編と遊びの質が変わる。**専用モード / 各海域の締め**として切り出すのが安全。
- 塞がれた列の扱いが理不尽にならないこと。塞がれた列は**視覚的に常に明示**する。

**実装コスト**: 大（モード1本ぶん）

---

## S2. 弾幕としての供給パターン ★★

**一言**: 瓦礫の降り方を**ランダムではなく譜面**にする。

現在の供給は重み付きランダム（§8.2）。ここに**パターン**を混ぜる。

| パターン | 形 | 要求される対応 |
| --- | --- | --- |
| **壁** | 両端2列に集中 | 中央で組み、端を早めに処理 |
| **柱** | 1列に連続投下 | その列を即座に崩す |
| **波** | 左端から右端へ順に1列ずつ | 追われながら組む |
| **雨** | 全列に薄く均等 | 平常時。現行のランダムに近い |
| **静寂** | 数秒間まったく降らない | **仕込みの時間**。連鎖を組みきる |

- パターンは**予告表示**する（水面に影が差す、など）。避けられない攻撃は攻撃ではない。
- **「静寂」が最も重要。** 常時高密度だと連鎖を組む余裕がなく、アクティブ連鎖が死ぬ。緩急を作る。

### なぜ実現可能か

R4 と同じく、**決定性シミュレーションが譜面を可能にする**。
パターンはシードではなく明示的なタイムラインとして持てる。

**実装コスト**: 中（パターン定義とエディタ）

---

## S3. 撃ち返し —— 沈降が岩を生む ★

**一言**: 落ちた氷塊は、**押し固められて岩になる。**

### ルール

スタックが **`|v| > 10 cell/s`** で海底に着地したら、衝撃で **岩ブロックが1個**生成される（着地列のいずれか）。

### なぜこのゲームらしいか

現状、沈降（失敗）のペナルティは「盤面が高くなる」だけで、**元に戻るだけ**。
岩は凍らないので（§7.2）、**取り返しのつかない負債**が積み上がる。
シューティングの「撃ち返し弾」に相当する、失敗の二次災害。

### リスク

- **デススパイラルを生む。** 一度失敗すると回復不能になりかねない。
  緩和案: 岩の生成はレベル4以降に限る / 生成確率を50%にする / リフリーズ（§5.5）に成功した塊は免除する。
  **リフリーズ免除は特に良い**——「落ちても諦めるな」という設計意図を強化する。

**実装コスト**: 小（ただしバランス調整のリスクが大きい）

---

## S4. 大気泡 —— 稼いで撃つボム ★

**一言**: シューティングのボム。ただし**配られない。稼ぐ。**

### ルール

- **5連鎖以上で水面到達**すると、大気泡チャージを1つ獲得（最大3つまでストック）。
- 発動すると海底から巨大な気泡が湧き、**盤面下2段を 1.5セルぶん持ち上げて**、その間の瓦礫を一時的に浮かせる。
- 発動操作は**両手で盤面を下から上へ同時スワイプ**（誤爆しにくく、ボタンを置かずに済む）。

### リスク

- **本作の失敗は遅い**（埋没までに猶予がある）。シューティングのような即死がないので、緊急回避の必要性が薄い。
  ボムの価値が低く、死に機能になる恐れがある。
- ボタンを置けない制約（§3.2）から、発動ジェスチャの誤爆・不発が起きやすい。

→ **優先度は低い。** 入れるなら「緊急回避」ではなく「**高連鎖への追加報酬**」として位置づける。

**実装コスト**: 中

# 4. スコアの乗算設計（全体を束ねる）

上記を採用すると、スコア倍率が**4軸の掛け算**になる。

```
score += k * 100
       * chainMult(chain)          // 連鎖の深さ         最大 5.55+（上限なし）
       * sameHit(k)                // 同時結氷           最大 1.50
       * kiwaBonus                 // 際結氷（T1）       1.00 or 1.30
       * resonance                 // ビート共鳴（R3）   chainMult に +0.3 として加算
       * syncBonus                 // 同期浮上（T3）     最大 2.00
       * reboostMult               // リフリーズ（§5.5） 1.00 or 1.50
```

- **4軸すべてを同時に満たすプレイ**が理論上の上限になる。Lumines や Rez と同じ「全部を重ねる」構造。
- 個々の倍率は控えめに設計し、**重なったときにだけ跳ねる**ようにする。
- 初心者は連鎖だけ見ていればよく、上級者には4軸ぶんの天井がある。**同じゲームで到達点が違う**。

# 5. 採用順の推奨

## 最優先（P1で入れる）

| 案 | 理由 |
| --- | --- |
| **T1 際結氷** | 実装コスト極小。既存の亀裂表示をそのまま判断材料に変え、**連鎖を遅らせる理由**という今ないものを作る |
| **T3 同期浮上** | 実装コスト極小。本作の核（指2本 vs 氷塊3本）に、**今ない報酬**を与える |

この2つは**新しい仕組みを何も足さず、既存の状態に対する判定と演出だけ**で成立する。
P0が終わって核が「面白い」と確認できた直後に入れるのが最も費用対効果が高い。

## 次点（P2〜P3）

| 案 | 理由 |
| --- | --- |
| **R1 融解の拍量子化** | リズムを外から被せず、**盤面が音楽を生む**。本作で最も「らしい」案。T1と強く噛み合う |
| **R2 潮汐 + R3 共鳴** | 「いつ凍らせるか」という3つ目の軸。ただし浮上予測ラインの積分対応が必須 |
| **S2 供給パターン** | 特に「静寂」の導入は、緩急としてリズム案抜きでも価値がある |

## 専用モード（本編が固まった後）

| 案 | 理由 |
| --- | --- |
| **S1 深海生物ボス** | 最も大きい案。**列＝照準、運動量＝ダメージ**という対応が見つかったので、新しい動詞ゼロで作れる |
| **R4 楽曲駆動モード** | 決定性シミュレーションの副産物として安価。譜面作成の工数が本体 |

## 保留

| 案 | 理由 |
| --- | --- |
| **T2 過冷却チャージ** | 指1本を長時間拘束する。6列で成立するかP1の実測待ち |
| **S3 撃ち返し** | デススパイラルのリスク。入れるならリフリーズ免除とセットで |
| **S4 大気泡** | 本作の失敗が遅いため、緊急回避の必要性が薄い。死に機能になる恐れ |

## 注意：P0 を守ること

**上記のどれも、P0（コア検証）より先に作ってはいけない。**

§13 で P0 の完了判定を「演出ゼロの矩形で、浮上中に2連鎖を繋ぐのが自分で楽しいか」と定めた。
ここが No なら、リズムもボスも救済にならない。**面白くない核に足しても、面白くない機能が増えるだけである。**

逆に P0 が Yes なら、T1 と T3 は**その週のうちに入れられる**ほど軽い。まずそこから。
