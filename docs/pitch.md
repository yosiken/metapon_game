# METAPON（メタポン）— 企画概要

> **「浮かび上がってる最中が、いちばん忙しい。」**

スマートフォンのブラウザで遊ぶ、海中が舞台のアクションパズル。1人用。

---

## 1. 30秒でわかるゲーム

海底にいる。上から瓦礫が降り積もり、埋もれたら終わり。

同じ色を3つ揃えると**凍って氷になる**。氷は浮くから、**上に乗った瓦礫ごと水面へ運び去る**。
ただし**氷は融ける**。ひとかたまりでは、まず水面まで届かない。

だから——**浮き上がっている最中に、次のマッチを作る。**
氷を継ぎ足し、連鎖を伸ばし、融けきる前に水面まで押し切る。

操作は**縦ドラッグだけ**。列の中でブロックを上下に動かす、それしかない。

---

## 2. 何が新しいのか

| 元ネタ | 受け継ぐもの | 変えたこと |
| --- | --- | --- |
| **メテオス** | 縦ドラッグ、3マッチ、浮力 vs 重量の物理 | 横10列 → **縦画面の6列**。打ち上げを「たまの爽快演出」から**常時の主戦場**へ |
| **パネルでポン** | アクティブ連鎖（動いている最中に次を仕込む） | 連鎖の舞台を平面の盤面から**浮上中の塊の内部**へ移した |

この2つの接続が企画の主題。**「マッチさせて終わり」ではなく「マッチさせてからが本番」。**

---

## 3. 設計の要：単発では、届かない

浮力は凍らせた数に比例し、重量は塊全体に比例する。
つまり**下の方で凍らせるほど、上に載った重量を背負う。**

| 状況 | 加速度 | 結果 |
| --- | --- | --- |
| 最上部で3マッチ | +8.0 | 即、水面へ |
| 上に5個ある状態で3マッチ | **−2.0** | 3セル浮いて沈む |
| 上に5個 + **浮上中に2連鎖目** | **+5.0** | 加速して水面へ |

**「浮かせてから連鎖を繋いで押し切る」ことがクリアの標準手順**になるよう、数値を組んである。
偶然の爽快感ではなく、**毎回そうしないと勝てない**。

---

## 4. 核となる緊張：指は2本、氷塊は3本

6列では、最大3つの氷塊が同時に浮いている。**しかし指は2本しかない。**

どれを伸ばし、どれを沈めるか——この取捨選択が毎秒発生する。
これが本作の上達曲線の中心であり、**6列でしか成立しない**（4列では塊が実質1本になり、判断が生まれない）。

---

## 5. 盤面が、自分でリズムを刻む

**氷は拍の上でしか融けない。** 融解タイミングを拍グリッドに量子化してある（BPM 150）。

- 盤面じゅうの氷が拍の頭に揃って砕け、融解音が**そのままパーカッションになる**。
- 繋ぐべき瞬間が**耳で分かる**。氷の見た目（亀裂の本数）も同じグリッドで段階表示される。
- **拍の直後に凍らせた氷は長持ちする**——リズムに乗る動機が、加点ではなく**物理から生まれる**。
- ただしリズムが取れなくても成立する。**ゲートではなく報酬。**

そのうえで、**際結氷（きわけっぴょう）**——融ける最後の1目盛りで次を繋ぐと、スコア×1.30・浮力×1.15。
これにより「早く繋ぐほど安全」だった連鎖に、**待つ理由**が生まれる。

---

## 6. 海中という設定が、ルールを説明する

単なる見た目ではない。**恣意的だった数値に、物理的な根拠がつく。**

| ルール | 海中での説明 |
| --- | --- |
| 速度に上限がある | **水の抵抗**による終端速度 |
| 効果が時間で切れる | **氷が融ける**。しかも**見た目で残り時間が分かる** |
| 凍った瞬間にひと押し進む | **凍結時の体積膨張** |
| 氷は掴めず、通り抜けられない | **凍りついている** |
| 海域ごとの難易度差 | **水温と塩分**。同じ水温が浮きやすさと融ける速さを同時に動かす |

「凍る瞬間に溶存気体が気泡として析出し、氷に抱き込まれる」——この一行が、
**気泡のVFXと「氷は時間で浮力を失う」を同時に説明する。**

## 7. スペック

| 項目 | 内容 |
| --- | --- |
| プラットフォーム | スマホのブラウザ（PWA対応 / オフライン可 / インストール不要） |
| 画面 | 縦固定。6列 × 12行。**両手持ち専用** |
| 操作 | 縦ドラッグのみ（同時2本指まで） |
| モード | スターツアー / エンドレス / タイムアタック(90秒) / チャレンジ / デイリー |
| 難易度調整 | 速度プリセット3段（ルールは変えず速度だけ変える） |
| 技術 | TypeScript + PixiJS + Vite。バックエンド不要 |
| 目標 | 60fps（iPhone SE2相当）、入力遅延50ms以内、バンドル500KB以内 |

**決定性シミュレーション**（シード付き乱数・固定60Hzステップ・sim層は純粋関数）を採用。
リプレイ、デイリー、自動バランステスト、将来の譜面モードが**すべてこの上に乗る**。

---

## 8. 開発計画：6〜8週

| Phase | 期間 | 内容 |
| --- | --- | --- |
| **P0 コア検証** | 2週 | 矩形と単色だけで物理を組む。**演出には一切進まない** |
| P1 連鎖システム | 1.5週 | 際結氷、拍量子化、浮上予測ライン |
| P2 難易度とモード | 1週 | レベルカーブ、モード群 |
| P3 演出と音 | 1.5週 | パーティクル、連鎖音階、チュートリアル |
| P4 仕上げ | 1週 | PWA、最適化、アクセシビリティ |

### P0 の合格条件

> **演出ゼロの矩形で、「浮上中に2連鎖を繋ぐ」のが自分で楽しいと感じられるか。**

ここが No なら数値を作り直す。**リズムも演出もモードも、面白くない核を救わない。**

---

## 9. 最大のリスクと対策

| リスク | 対策 |
| --- | --- |
| **浮上中の操作が難しすぎる**（本作の全て） | 浮上予測ライン、氷の輪郭発光、速度を視線が追える範囲に抑える。P0で未経験者に触らせて判断 |
| **6列は初心者に情報量が多すぎる** | 速度プリセット「ゆっくり」が唯一の緩和策。チュートリアルで列を段階的に開ける |
| **海中の青一色で視認性が落ちる** | 背景は低彩度の青に限定し、**ブロックの色相から青系を外す** |

---

## 10. この企画の一行

**「氷が融けきる前に、次を凍らせろ。」**

操作は縦ドラッグだけ。動詞はひとつ。
そこに**物理・リズム・取捨選択**が全部乗っている。
