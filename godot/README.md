# METAPON モック（Godot 4）

`docs/game-design.md` の **P0: コア検証**（§13）用のモック。
演出は矩形と単色のみ。「浮上中に2連鎖を繋ぐのが自分で楽しいか」を判定するためのもの。

## 動かす

```
godot --path godot            # Godot 4.3 以降
```

または Godot エディタで `godot/project.godot` を開いて F5。

### 操作

| 操作 | 内容 |
| --- | --- |
| ドラッグ（縦） | 列の中でブロックを上下に動かす。同時2本指まで（§6.1 / 6.2） |
| `space` | 一時停止 |
| `.` | コマ送り |
| `s` | スロー再生 0.25x |
| `r` | リセット |
| `d` | デバッグパネル |

デバッグパネルで速度・沈降係数・レベル固定を変えられるほか、
**拍量子化（§4.6）・際結氷（§5.8）・氷は壁（§5.6）を個別にオフにできる**。
P0 の問い（核そのものが面白いか）を、後から足した仕組み抜きで確かめるため。

## テスト

```
godot --headless --path godot --script res://tests/spec_check.gd      # 仕様書 付録B との一致
godot --headless --path godot --script res://tests/headless_check.gd  # 3分×2シードのスモーク + 決定性
```

`spec_check` は付録B「数値の検算シート」の5ケースを実際に盤面で再現し、
重量・浮力・加速度・初速・融解時刻のグリッド整合を検証する。

スクリーンショットを撮る場合（要 xvfb）:

```
xvfb-run -a godot --path godot --script res://tests/scenario_shot.gd --resolution 540x960
```

## モックでの仕様からの逸脱

1. **1列につき水中スタックは1本まで。** 仕様（§5.1）は「上限3本、超過時は最寄りに統合」だが、
   モックでは重なりを避けるため、既にスタックが載っている列の海底マッチは、その列が空くまで持ち越す。
2. **着地時の再配置が簡略。** 沈降したスタックは各列の海底の上にそのまま積み直す。
   列ごとに海底の高さが違う場合、見た目が一瞬飛ぶ。
3. **音が無い。** §4.6 の眼目は「融解音がパーカッションになる」ことなので、
   ここはモックとしては最大の欠落。HUD の拍インジケータで拍だけ可視化している。

## テストプレイで見てほしいこと

P0 の合格条件は「**演出ゼロの矩形で、浮上中に2連鎖を繋ぐのが自分で楽しいか**」（§13）。
それ以外は全部あとから直せる。以下は判断材料。

### 1. まず確かめる（これが No ならパラメータを作り直す）

- [ ] 浮上中の塊に指を入れて、2連鎖目を繋げたか
- [ ] 繋げたとき「押し切った」感触があったか。単に数字が増えただけに感じないか
- [ ] 赤い予測ラインを見て「あと1連鎖で届く」と判断できたか

### 2. 操作

- [ ] 浮上中の塊のブロックが掴みにくくないか（動いている対象を掴む難しさ）
- [ ] 指でブロックが隠れて見えないか
- [ ] 氷が壁になって動かせないことが、理不尽ではなく読みの要素に感じられるか
  → 理不尽なら デバッグパネルの「氷は壁」をオフにして比較

### 3. 拍量子化と際結氷（デバッグパネルで個別にオフにして比較）

- [ ] 氷の亀裂3本＋シアン発光（＝際窓）に気づいたか。狙えたか
- [ ] 「拍量子化」をオフにすると、融解タイミングが読みにくくなるか
  → 差を感じないなら、音が無い状態では拍量子化は機能していない

### 4. 難易度

- [ ] 何秒で埋没したか（初見で2〜4分が目標。§13 P2）
- [ ] 緩すぎる / 忙しすぎる、どちら寄りか

### 報告してほしい数値

デバッグパネル（`d`）に出る **最大連鎖 / 際結氷率 / 浮上・沈降回数**、
それと**生存時間**。パラメータ調整の起点になる。

## 観察メモ

- スモークテストで **浮上47回 / 沈降47回**（seed 20260921, 3分）。
  単発では届かず約半数が沈むという §4.4 の設計意図どおりの比率になっている。
- ランダム入力のボットでも3分間 **埋没しなかった**。
  難易度が緩い可能性があり、`dropRate` かレベル到達時刻の見直しが要るかもしれない（P2 で実測）。
- ボットの際結氷率は 0〜7%。人間が狙ったときどこまで上がるかが P1 の観測対象。

## 技術構成についての注記

仕様書 §12.1 の技術構成は **TypeScript + PixiJS + PWA**（ブラウザ配信が前提）。
本モックはプロトタイプとして Godot 4 / GDScript で作っている。
Godot を本番にも使うか、モック限りにするかは未決（Godot は Web 書き出しができるが、
バンドルサイズと初回ロードの目標値 §2.2 を満たせるかは別途検証が要る）。

sim 層（`scripts/sim/`）は描画・入力・エンジンAPIに依存しない純粋なロジックにしてあるため、
仮に TypeScript へ移す場合もそのまま移植できる。
