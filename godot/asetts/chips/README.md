# チップ画像

提供された 10x10 のシート画像から切り出したもの。
`tools/slice_chips.py` で再生成できる。

```
python godot/tools/slice_chips.py <シート画像> --out godot/asetts/chips
```

| フォルダ | 中身 |
| --- | --- |
| `all/` | 全100枚。`r<行>c<列>.png` |
| `unique/` | 重複を除いた40種 |
| `pick5/` | ゲームで使う5色の推奨セット |
| `ice/` | **氷結演出用の3枚**（実装済み）|
| `_contact_*.png` | 確認用の一覧（水中の背景色を敷いてある） |

いずれも **透過PNG 128x128**。黒背景を輝度からアルファに変換し、
宝石の外接矩形で正方形に整えてある。水中の背景に重ねても黒縁が出ない。

## 重複判定について

**このシートにピクセル完全一致の重複は無かった。** 一見同じに見える宝石も、
拡大するとハイライトの位置や面の切り方が全て異なる、別々のスプライトだった。

そのため判定基準を「**盤面の実サイズ（約60px）で見分けがつくか**」に置いている。
原寸で見比べれば違いは分かるが、プレイ中のセルサイズでは区別できないものは、
ゲーム的には同じチップとして扱うべきという考え方。

`slice_chips.py` の `--play-size`（既定60）と `--threshold`（既定25）で調整できる。
しきい値を上げれば種類は減る（20で51種、30で25種）。

## pick5 の選び方

ゲームが必要とする色数は最大5（仕様書 §8.1 `COLORS_MAX`）。
`tools/pick_chips.py` で選び直せる。

```
cd godot && python3 tools/pick_chips.py
```

### 制約

1. **青〜青緑（色相 150〜265°）を除外**。背景が青い水中であることに加え、
   氷結演出が青いチップ3枚なので、青は「凍っている」の専用色にする（§11.2）。
   40種のうち19種が青系で、残る21種から選ぶ
2. **色覚特性に関わらず区別できること**。正常色覚・1型(P)・2型(D)・3型(T) の
   4通りで CIELAB 距離を測り、**その最悪値**が最大になる組を総当たり（20349通り）で選ぶ。
   「正常色覚で離れている」だけでは不十分

### 結果

| | ファイル | 色 | チップの形 | シンボル |
| --- | --- | --- | --- | --- |
| color0 | `r0c2` | 赤（1°） | 丸 | ● |
| color1 | `r0c4` | 金（45°） | 丸 | ▲ |
| color2 | `r8c1` | 緑（142°） | 星 | ★ |
| color3 | `r6c6` | 紫（282°） | カイト | ◆ |
| color4 | `r5c9` | 白（オパール、彩度0.09） | 球 | ■ |

色の最悪値 **22.4**（4通りの色覚 × 全10ペアの最小 ΔE）。
`_contact_pick5.png` が4通りのシミュレーション結果。

### 形の扱い

21種は丸と八角が大半で、**5枚すべてを違う輪郭にはできない**。
赤と金はどちらも丸いチップで、輪郭の距離は 0.017 しかない。
そのため形の判別は**ブロックに重ねるシンボルが担う**前提で、色の方を最大化している。
シンボルはチップの輪郭となるべく揃えてあり（緑=星、紫=カイト）、
赤と金の区別だけはシンボル（●と▲）が唯一の手がかりになる。

### 前の選定（2026-09-21 に差し替え）

以前は `r0c2`(赤八角) / `r1c6`(緑八角) / `r2c7`(橙星) / `r5c9`(白丸) / `r8c6`(青緑角型)
だった。差し替えた理由は2つ。

- **赤と緑がどちらも八角で、2型色覚では色も ΔE 15.6 しか離れていなかった**。
  色でも形でも区別できないペアが残っていた（色の最悪値は 7.8。現行の 1/3）
- **`r8c6` が青緑**で、氷結演出に青いチップを採用した後は「半分凍っている」
  ように見えてしまう

## ice/ — 氷結演出（実装済み）

青くて四角いチップ3枚を、氷のアニメーションとして使っている（仕様書 §6.4.1）。

| | ファイル | 備考 |
| --- | --- | --- |
| ice0 | `r1c0` | 八角。3枚の中で最も濃い |
| ice1 | `r2c8` | 角型、H字の面 |
| ice2 | `r3c2` | 同上。ice1 とはごく僅かな差 |

**ice1 と ice2 がほぼ同じなのは意図的。** アニメーションのコマとしては
微差の方が「氷の表面で光が動く」表現になる。形が大きく変わると
宝石が別物に変形したように見えてしまう。

### なぜ青なのか

色付きブロックは背景（青い水中）と同化しないよう**青系を外してある**（§11.2）。
その結果、**青は氷にしか現れない色**になり、凍ったことが一目で分かる。

### コマ送りは拍に同期している

`main.gd` の `_draw_ice()` が `(sim.frame / grid_frames) % 3` でコマを選ぶ。
つまり8分/16分ごとに絵が切り替わる。§4.6 の「盤面が音楽を刻む」を
**音を消していても目で見えるようにする**ためで、ブロックごとに位相を
ずらして盤面全体が一斉に同じ絵になるのを避けている。

残り時間（何目盛りか）はチップの上に亀裂の本数と際窓の脈動で重ねている。
§5.8 の判断材料なので、絵に埋もれさせないこと。

## 色ブロックはまだ実装に入れていない

現在のモックは `main.gd` の `_draw_block()` が矩形とシンボルを直接描いている
（仕様書 P0 の「演出は矩形と単色のみ」に従っている）。
これらのチップに差し替えるかは未定。差し替える場合は `Cfg.COLORS` の
5色と対応させ、色覚シミュレータでの確認（§11.2）を併せて行うこと。
