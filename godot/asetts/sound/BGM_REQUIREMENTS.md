# BGM 発注仕様（METAPON）

> **状態: 130 BPM の `Deep_Underwater.ogg` を採用済み**（`README.md` の節4-5参照）。
> 以下は次回 BGM を追加/差し替える際の仕様として残す。

このゲームは **氷の融解音が拍グリッドの上でしか鳴らない**（仕様書 §4.6）。
つまり **ゲーム自身が打楽器を演奏する**。BGM はその上に乗る伴奏であって、主役ではない。

普通のゲームBGMと最も違うのはこの一点で、**BGM は「場所を空ける」ことが仕事**になる。

---

## 1. 最優先：ゲームの打楽器と場所を奪い合わないこと

ゲームが鳴らす融解音の密度:

| レベル | グリッド | 融解音の最大密度 |
| --- | --- | --- |
| Lv1〜4 | 8分（230.8 ms） | 最大 **4.3 回/秒** |
| Lv5以降 | 16分（115.4 ms） | 最大 **8.7 回/秒** |

**つまりゲームは常に8分〜16分の刻みを叩いている。**

- **16分のハイハット/シェイカーは入れない。** 完全に食い合う
- キックとスネアも**控えめに**。4つ打ちは可だが、シンプルに
- パーカッションを足すなら**2小節以上の長いスパン**で動くもの
- 「リズムが薄い」と感じるくらいでちょうどよい。**足りない分はゲームが叩く**

### 帯域

融解音・結氷音は氷の質感（明るく硬い）なので **2〜8 kHz** を使う。

- BGM は **低域〜中低域中心**（サブベース、ベース、パッド）
- 2〜8 kHz を空けておく。シンバル、明るいベル、きらびやかなアルペジオは避ける

---

## 2. 単一キー・転調なし（★見落としやすい）

結氷音は**連鎖数に応じてメジャースケールで音階が上がる**（§11.1）。

```
連鎖 1  2  3  4  5  6  7  8 ...
半音  0  2  4  5  7  9 11 12 ...
```

BGM が転調すると、高い連鎖のときの結氷音が**ぶつかる**。

- **曲全体を1つのキーで固定**。転調・複雑なコード進行を避ける
- ドローン／モーダル／2〜4コードのループが望ましい
- **キーを教えてほしい。** 結氷音の基準ピッチをそのキーのトニックに合わせる

---

## 3. 拍とループ

| 項目 | 要件 |
| --- | --- |
| BPM | **130 固定**（採用済み）。テンポ変化・ルバート・生演奏の揺れは不可 |
| 拍子 | 4/4 |
| 先頭 | **1小節目の頭から音が始まる。先頭無音ゼロ**（フェードイン不可） |
| 末尾 | **フェードアウト・末尾無音なし。** 頭に戻って繋がること |
| 長さ | **小節の整数倍**。下表から選ぶ |
| 形式 | **ogg**（44.1 kHz または 48 kHz） |

```
 32 小節 =  59.077 s = 0:59.08
 48 小節 =  88.615 s = 1:28.62
 64 小節 = 118.154 s = 1:58.15      ← 推奨
 96 小節 = 177.231 s = 2:57.23      ← 推奨
128 小節 = 236.308 s = 3:56.31
```

> 前回の `Breathing Spaces` は先頭に127ms、末尾に2.29秒の無音があり、
> 全長も小節の整数倍でなかった（0.41小節ぶんずれる）。
> **書き出し時にここを詰めるのが最重要。**

## 4. 曲の性格

1プレイは 30秒〜10分と幅があり、**プレイヤーは曲のどこから聴き始めるか分からない**。

- **起伏の少ないループ**にする。ドラマチックなイントロ／ブレイクダウンは避ける
- 難易度の起伏はゲーム側のレベルカーブが作る。曲が勝手に盛り上がると画面と食い違う
- 「ずっと同じテンションで回り続ける」ものが正しい

## 5. 世界観（§1.0）

海中。海底から水面へ。危険域では画面が暗く濁り、BGM にローパスがかかる（§4.5）。

- **ローパスをかけても成立する**こと。高域に依存した曲は危険域で消える
- リバーブ／ディレイは深めでよいが、**リズムを滲ませない程度**に
- サブベースの持続音は水圧感が出るので相性がよい

### 参考になる方向性

- ダブテクノ、ミニマル、アンビエントテクノ寄り
- 水中／深海をテーマにしたアンビエント（ただしビートは保つこと）
- **避けたいもの**: EDM系の派手なビルドアップ、16分刻みのシンセ、ブレイクビーツ

## 6. 納品後にこちらで確認すること

```
python godot/tools/analyze_bgm.py "godot/asetts/sound/bgm/<file>.ogg" --assume-bpm 130
```

- 実測テンポが 130 か
- 先頭無音が 0 か
- 全長が小節の整数倍か

数値が合っていれば `cfg.gd` の `BPM` / `TICKS` を 130 にして、そのまま鳴る。

## 補足：SE 側の要望（既存音の差し替え）

BGM とあわせて直せるとよいもの。実測値は `README.md` を参照。

| 優先 | 内容 |
| --- | --- |
| **高** | `Melting.wav` を **200 ms 以下**に。16分（115 ms）で連打されるため、現状616 msでは団子になる |
| **高** | 全SEの**先頭無音（42 ms）を詰める**。16分の36%にあたり、打楽器が拍の後ろにずれる |
| 中 | **際結氷の専用音**（§5.8）。いまは結氷音を1オクターブ上げて代用。区別がつかないと狙えているか分からない |
| 低 | 着地の専用音。いまは融解音を0.62倍ピッチで代用 |
